# Envio HyperIndex for Flurbo

Target bounty: Best use of Envio. Monad testnet (10143) only.

> Status (8 Oct 2026): the indexer is deployed on Envio Cloud and synced for the six pools listed so far. Reading it on 8 Oct returned 35 trades and redemptions across 6 pools, 10 distinct trader addresses and 51.24 test AUSD of volume (testnet, includes team testing). The Kuru and receipt-wrapping events described below are in this repository but take effect only after the Envio release is redeployed from it (section 6).

## 1. What it indexes and why

A Flurbo pool prices one-to-three question claims over a shared pool, so its useful history is not a price chart: it is who bought which claim, what they paid, who redeemed, how the optimistic resolver moved, and now where receipts of those claims traded on Kuru. Reading that from `eth_getLogs` on a public RPC is rate limited and, on Monad testnet, capped at 100 blocks per request. The indexer turns the events into queryable entities.

The indexer is the history view. Current quotes, balances and outcomes always come from the pool through a fresh chain read; the pages say so.

## 2. Pipeline

```
Monad testnet logs ──> Envio HyperIndex ──> GraphQL (Envio Cloud) ──> POST /envio (bounded queries) ──> web app
 PilotPool, PilotResolver,                    config.yaml, schema.graphql,
 Kuru markets                                 src/handlers/Flurbo.ts
```

- [`config.yaml`](../packages/envio-indexer/config.yaml) is generated by [`scripts/generate-config.mjs`](../packages/envio-indexer/scripts/generate-config.mjs) from `config/collections.json` (active pools and resolvers) and `config/kuru-listings.json` (verified Kuru markets), so adding a pool to the registry adds it to the index. `npm run config` regenerates it, and a test fails if the committed file drifts.
- Events: `Traded`, `Redeemed`, `BaseWrapped` and `BaseUnwrapped` on pools; `Asserted`, `Disputed`, `Finalized` and `Delivered` on resolvers; `Trade`, `OrderCreated` and `OrderCanceled` on Kuru markets. The transaction hash is selected for every event.
- Handlers: [`src/handlers/Flurbo.ts`](../packages/envio-indexer/src/handlers/Flurbo.ts). A generated module maps each Kuru market to its pool and question, so handlers need nothing outside the package.

## 3. Entities

| Entity | Holds |
|---|---|
| `Pool` | trade count, volume and redeemed amount |
| `TraderPosition` | per trader and pool: total cost, proceeds, redeemed and net cash movement over the indexed window |
| `Trade` | each buy, sell or redemption with its claim (scope, mask), quantity, amount, block and time |
| `ResolutionEvent` | each assertion, dispute, finalization and delivery |
| `ReceiptFlow` | a claim wrapped into, or unwrapped from, its receipt token, with the transaction hash |
| `KuruMarket` | one receipt order book: its pool and question, fill count, filled volume, orders created and cancelled, last price |
| `KuruFill` | each fill: maker, taker, side and price as Kuru emitted them, size, block, time and transaction hash |

Net cash movement is what a trader paid and received in the indexed window. It is not marked-to-market profit, a current balance or current holdings, and the app does not call it that.

## 4. Where the app uses it

- **What If** shows "Recent pool activity · Envio" (`apps/web/src/components/EnvioActivity.tsx`).
- **Portfolio** shows indexed cash movement per pool (`EnvioPortfolioSummary.tsx`).
- **Kuru order book page** shows "Recent fills · Envio" with each fill's transaction (`KuruFills.tsx`).
- The browser never sends GraphQL: it posts a small JSON request to `/envio`, and the server (`apps/web/server/envio-proxy.mjs`) maps it to one of four fixed, bounded queries (`trades`, `position`, `portfolio`, `kuru-fills`), holds the endpoint and any credential, and refuses anything else. Tests cover each query and the refusals.

## 5. Checked

- `npm run codegen` and `tsc --noEmit` pass with the real Envio toolchain (run in WSL), with and without Kuru markets listed.
- The generator is unit tested, including a test that the committed configuration equals its output.
- Earlier local sync (3 Oct): 37 trade or redemption rows and 27 resolution rows for six pools, and one indexed trade matched its Monad RPC log in trader, scope, mask, quantity and amount.
- Browser tests cover the three pages above against a mocked proxy.

## 6. Deploying a release

Envio Cloud deploys a branch of the repository: root directory `packages/envio-indexer`, config `config.yaml`. After merging this work to the branch the cloud indexer follows, wait for the new deployment to sync, then check that `{ Pool(limit: 20) { id } }` returns every listed pool. If the endpoint URL changes, update `FLURBO_ENVIO_GRAPHQL_URL` on the web service. After the Kuru markets are listed, the first Kuru sell should appear as a `KuruFill` whose transaction hash equals the recorded hash.
