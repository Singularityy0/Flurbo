Listing markets: the whole process

Any number of pools can be listed in one batch. Each pool has 2 to 4 yes or no questions, one trading close, its own liquidity and its own payout. Combinations work only inside a pool. In registry mode no Render settings change per pool: the commit to config/collections.json is the listing.
StepCommandWhoTouches the chain
1. Write the batch fileCreate config/markets/<name>.json (template below)AuthorNo
2. Preparebun workflows/cre/scripts/batch.ts prepare --spec config/markets/<name>.jsonAuthorReads sources
3. Checkbun workflows/cre/scripts/batch.ts check --ids a,bAuthorReads balances
4. Simulate (optional)Deploy command without --account and --broadcast, then delete the <id>-unverified.json files it writesAuthorReads only
5. DeploySee belowOwner (keystore password)Yes, spends gas and funds pools

7. Registerbun workflows/cre/scripts/batch.ts register --ids a,b [--feature a]AuthorNo
8. Commit and mergeCommit config/collections.json and the batch file; open a PR; mergeOwnerNo. Render redeploys; the site lists the pools and the bot settles them.

Deploy command (step 5)

FOUNDRY_PROFILE=demo FLURBO_DEPLOYER=0xf1fea08ebba92ed342acc5639db312c3694bc391 FLURBO_DEPLOY_IDS=a,b forge script contracts/script/DeployPilotBatch.s.sol:DeployPilotBatch --use target/tools/solc-0.8.28.exe --rpc-url https://testnet-rpc.monad.xyz --account flurbo-testnet --sender 0xf1fea08ebba92ed342acc5639db312c3694bc391 --broadcast --slow

Timing rules: each pool's deploy transaction must land more than one hour before its trading close. Trading on the site opens when the registry commit is merged, so deploying early and merging later is fine. A pool whose answer is captured at time T must be merged before T, or the bot will not know about it.

Other registry edits: batch.ts set <pool or label> settlement=finish-only, status=retired, or featured. The release pilot's mode is the top-level pilotSettlement field.

Writing rules that settle cleanly

Reader cheat sheet

ReaderUse forKey settingsExample
json-api.v1Any public JSON APIselect (JSON Pointer), aggregate: value, only, count, sum, max, min; field; up to 8 filter (eq, ne, gt, gte, lt, lte); up to 8 checks (exact equality)BLS API, NY Fed SOFR, USGS count, NWS observations, GFZ Kp, GitHub releases, TSE results

Checklist

  1. Official first-line source only. Publishers' own APIs or pages; no aggregators or news sites. No sources that need a login, a paid key, JavaScript to render, or a PDF.
  2. The question names the exact source, measure and capture window. Anyone must be able to check the answer from the text alone.
  3. Fail closed. Design the reader so a format change produces no reading rather than a wrong answer. Prefer reading one item's own field (aggregate only with a unique filter) over counting matches, because a renamed field silently counts 0. A missing value, 404 or null is never treated as No.
  4. Prediction guard. Trading closes before every capture window. The rule check refuses a value that is already public.
  5. Settle wait. For data about an interval (observation.period written as start/end), open the window at least 3 hours after the interval ends. Chain readers are exempt because they wait for finality.
  6. Small responses. Keep each response well under 500 KB (the hard cap is 2 MB). Captures are stored in Redis on a free plan. Narrow queries with dates.
  7. Exact URLs. Write URLs in normalized form (for example https://rpc.monad.xyz/ with the trailing slash), with no API keys.
  8. Chain state is short-lived. The public Monad RPC keeps contract state only a few days: capture price and supply reads within hours of at.
  9. Thresholds near the current value so both answers are plausible; set prices at prepare time.
  10. Shared rate limits. The BLS v1 API (about 25 requests a day per IP) and the GitHub API (60 an hour unauthenticated) are shared with other tenants of Render's IP addresses; prefer short windows and expect manual fallbacks.
  11. Topics. No sports, pop culture or awards. Elections are allowed from official results only.
  12. No em dashes or emojis in question text.
