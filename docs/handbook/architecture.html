How Flurbo runs

Written 1 October 2026 from the code on main (merge of PR #31) and the live /healthz. Monad testnet only, test assets only.

Flurbo is a prediction market where related yes or no questions share one pool. Each pool prices its 2 to 4 questions together with one logarithmic market scoring rule (LMSR), so people can buy single answers or combinations (AND, OR, exactly one, at least two). Answers settle from official public sources through a bonded, challengeable proposal on-chain.

Data stores

Upstash Redis

Database solid-fly-322049.upstash.io, free plan (500,000 commands a month, no card on file). Holds sessions, agents and their heartbeats, wallet links, settlement journals, monitor state, captured source evidence, email dedupe and the starter-funds ledger.

Supabase

Same project as access applications. With FLURBO_SUPABASE_KV=true, rebuildable data lives here: price history, trade index, payout index and operator metrics (prefixes flurbo:prices:, flurbo:pilot:index:, flurbo:pilot:payouts:, flurbo:metrics:). Migrations are in apps/web/server/migrations.

Monad testnet

Chain 10143. Test AUSD 0xa9012a055bd4e0edff8ce09f960291c09d5322dc (6 decimals). Read through a QuickNode endpoint stored as FLURBO_ALCHEMY_TESTNET_RPC_URL (the name is historical).

Monad mainnet (read only)

Chain 143, https://rpc.monad.xyz/. Used only by evm-rpc.v1 rules (Chainlink price feeds, token supplies, transaction counts). The public RPC keeps contract state for only a few days.
