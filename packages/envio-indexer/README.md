# Flurbo Envio HyperIndex

This indexer follows active Monad testnet pools and resolvers from `config/collections.json`, and the verified Kuru order books of YES receipts from `config/kuru-listings.json` (the combined verified listings, no secrets). Run `npm run config` after registry or listing changes. It indexes the real `Traded`, `Redeemed`, `BaseWrapped`, `BaseUnwrapped`, `Asserted`, `Disputed`, `Finalized`, and `Delivered` events emitted by the pool and resolver contracts, and Kuru's `Trade`, `OrderCreated` and `OrderCanceled` events. Entities: `Pool`, `TraderPosition`, `Trade`, `ResolutionEvent`, `ReceiptFlow` (a claim wrapped into or unwrapped from its receipt), `KuruMarket` (fill and order counts) and `KuruFill` (each fill with its transaction hash). Kuru prices are stored as emitted. It stores trade volume and each trader's cash movement in the indexed window. It does not claim a current collateral balance, realized profit, or current holdings from events alone.

Local development requires Linux Node 22 or newer, Docker, and an `ENVIO_API_TOKEN` from Envio. On Windows, use WSL2 with Docker Desktop integration. Run `npm ci`, `npm run config`, `npm run codegen`, `npm run typecheck`, then `npm run dev`. The web deployment and smoke-test steps are in [`docs/ENVIO_MAIN_DEPLOYMENT.md`](../../docs/ENVIO_MAIN_DEPLOYMENT.md).
